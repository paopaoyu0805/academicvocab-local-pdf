# AcademicVocab 同步规则

## 1. 本文范围

本文定义手机、Zotero 插件和未来 Supabase 之间的同步行为。当前阶段不连接网络、不创建同步代码或数据库。

## 2. 同步参与方

### Android PWA

- 使用已登录用户会话；
- 保存手机本地 PDF 选词结果；
- 支持离线待发送队列；
- 不在队列中保存 PDF、腾讯密钥或服务端高权限密钥。

### Zotero 插件

- 使用后续一次性配对流程获得可撤销设备身份；
- 保存 Zotero 选词和标记的本地所有权账本；
- 处理翻译、保存和标记移除的待办；
- 不保存用户密码或 `service_role`。

### 服务端

- 从验证后的会话或设备身份确定用户；
- 执行查重、用户隔离、翻译额度和任务状态转换；
- 返回服务端最终记录，不相信客户端提交的 `user_id`、额度或标记所有权。

## 3. 通用同步信封

每个会改变数据的请求未来都必须包含：

- `request_id`：客户端生成的随机 UUID；
- `device_id`：已配对设备标识；
- `operation`：固定允许列表中的操作；
- `client_created_at`：仅用于显示和排查，不能替代服务端时间；
- 操作所需的最少业务字段。

服务端响应包含：

- 相同的 `request_id`；
- `completed`、`pending`、`conflict`、`quota_paused` 或 `failed`；
- 服务端记录 ID 和最新版本；
- 固定错误代码，不返回密钥、SQL 或第三方原始错误。

同一用户的相同 `request_id` 重试必须返回同一结果，不重复创建记录或消耗翻译额度。

## 4. 生词录入流程

手机和 Zotero 使用相同的逻辑：

1. 客户端在本地规范化单词和例句。
2. 用户确认单词、例句、文献和页码。
3. 客户端创建稳定的 `request_id` 并写入本地待发送队列。
4. 服务端按 `user_id + normalized_word` 查找或创建 word。
5. 服务端按来源创建或复用 document。
6. 服务端计算并检查 example `dedupe_key`。
7. 新例句写入；重复例句返回已有记录。
8. 缺少翻译时分别创建 `translate_word` 和 `translate_example` 任务。
9. 服务端返回权威 word、example 和翻译状态。
10. 客户端确认收到后才从本地待发送队列移除该请求。

网络中断时保留队列。重复点击或重复发送不能创建第二个相同单词或例句。

## 5. 自动翻译同步

翻译任务处理顺序：

1. 验证任务、用户和目标记录属于同一用户。
2. 如果用户修订字段已经有值，仍可更新机器字段，但不能覆盖用户字段。
3. 按提供商、语言和源文本哈希检查用户自己的缓存。
4. 缓存命中时直接完成，不增加腾讯字符用量。
5. 缓存未命中时，由服务端原子检查项目当月 500000 字符上限。
6. 未超限才增加本月用量并调用腾讯。
7. 成功后写入缓存和机器翻译字段。
8. 超额时设置 `quota_paused`，不调用腾讯。
9. 临时网络错误进入延迟重试。
10. 认证、计费或配置错误直接停止自动重试，等待人工处理。

翻译任务的 `idempotency_key` 必须由目标类型、目标 ID、源文本哈希、语言方向和提供商共同生成。

同一腾讯账户可能还被其他插件使用，因此项目计数只是额外保护，腾讯后付费关闭仍是启用前提。

## 6. 离线队列

客户端本地队列只保存：

- `request_id`；
- 操作类型；
- 必需的单词、例句和来源元数据；
- 重试次数和下次重试时间。

队列不得保存：

- PDF 文件或 Base64；
- 腾讯 SecretId、SecretKey；
- 用户密码；
- Supabase `service_role`；
- 第三方插件账号或内部配置。

重试采用延迟增长，并设置最大次数。超过上限后保留失败记录，提示用户手动重试，不能静默丢弃。

## 7. 并发和冲突

### 追加型数据

examples、review_events 和 sync_jobs 优先使用唯一键与幂等写入，不使用“最后写入覆盖整表”。

### 可编辑数据

words 的用户释义、生命周期状态等字段使用 `row_version`：

- 客户端提交其读到的版本；
- 服务端只在版本匹配时更新；
- 版本不匹配时返回 `conflict` 和服务端最新数据；
- 客户端不得静默覆盖较新的用户修改。

机器翻译字段与用户修订字段分离，因此后台翻译不参与用户字段冲突。

### 标签

word_tags 按单条关系添加或移除。添加使用唯一约束保证幂等，不用整组标签覆盖其他设备刚添加的标签。

### 时间

服务端时间决定 `created_at`、`updated_at`、额度月份、任务租约和状态顺序。客户端时间只作为辅助信息。

## 8. 复习同步

每次复习使用唯一 `client_request_id`：

1. 服务端检查该复习事件是否已存在；
2. 不存在时追加 review_event；
3. 在同一事务中更新 review_state；
4. 已存在时返回原结果，不重复推进复习间隔。

如果 word 已经 `paused`、`mastered` 或 `archived`，客户端不得继续创建正常复习事件。

## 9. “不再复习”同步

用户点击“不再复习”并确认后：

1. 使用 `row_version` 把 word 改为 `mastered`；
2. 保留 word、examples、documents、review_states 和 review_events；
3. 查找该词所有 `active` Zotero marker；
4. 每个 marker 创建唯一的 `remove_zotero_marker` job；
5. 电脑关闭时 job 保持 `pending`；
6. Zotero 插件以后取得 job 时，必须同时核对云端记录和本地所有权账本；
7. 核对通过才按准确 annotation key 删除；
8. 删除成功后 marker 设为 `removed`，job 设为 `completed`。

幂等规则：

- 同一 marker 只允许一个未完成移除任务；
- 标记已经不存在时记录审计信息并视为完成；
- 标记被用户修改或本地账本丢失时设为 `protected_modified` 或失败，不得猜测删除；
- 云端确认失败时保留本地完成凭据并安全重试确认，不再次删除其他标记。

详细标记安全规则留到阶段 1D。

## 10. 任务租约和恢复

处理任务时：

- worker 把 `pending` 改为 `processing`，并设置短时租约；
- 只有租约持有者可以提交本次结果；
- 进程崩溃或电脑关闭后，租约到期可恢复为待处理；
- 每次尝试递增 `attempt_count`；
- 超过最大次数进入 `failed`；
- `quota_paused` 不进行高频重试，新月份或用户明确恢复后才重新排队。

## 11. 固定错误类别

客户端只处理稳定错误代码：

- `AUTH_REQUIRED`；
- `DEVICE_REVOKED`；
- `VALIDATION_FAILED`；
- `CONFLICT`；
- `DUPLICATE`；
- `TRANSLATION_PENDING`；
- `TRANSLATION_QUOTA_PAUSED`；
- `TRANSLATION_PROVIDER_ERROR`；
- `MARKER_OWNERSHIP_UNVERIFIED`；
- `RETRY_LIMIT_REACHED`。

错误消息不得包含密钥、令牌、SQL、完整第三方响应或私人正文。

## 12. 不同步的内容

第一版明确不同步：

- PDF 和全文；
- 本地绝对文件路径；
- Zotero SQLite 数据库；
- Magic 或其他插件的翻译缓存；
- 腾讯和 Supabase 私密密钥；
- 用户密码和原始一次性配对码；
- 未经用户确认的临时选区。

## 13. 后续实现要求

真正实现同步前必须：

- 先通过 Zotero 选词、标记所有权和 Android PDF 选词技术验证；
- 用数据库 migration 建立外键、唯一约束和 Row Level Security；
- 使用两个测试用户验证互相不可读取；
- 测试断网、重复发送、并发编辑、worker 崩溃和跨月额度；
- 不通过删测试、放宽约束或使用高权限前端密钥取得通过。

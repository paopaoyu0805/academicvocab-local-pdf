# Zotero 标记保护规则

## 1. 目的与范围

本文规定 AcademicVocab 在 Zotero 中创建、记录和移除标记时必须遵守的安全边界。阶段 3 仅在隔离开发 profile 与受控测试 PDF 中验证这些规则；日常 Zotero、正式资料库和私人 PDF 不在范围内。

AcademicVocab 标记必须是由插件通过 Zotero 官方标注能力创建的独立 Zotero 标注。项目永远不修改原始 PDF，也不直接修改 Zotero SQLite 数据库。

## 2. 本地所有权账本

插件以后必须维护本地所有权账本。账本是判断标记是否由 AcademicVocab 创建的必要证据，至少记录：

- 本地账本 ID；
- `word_id` 和 `example_id`；
- Zotero library ID；
- parent item key；
- attachment key；
- annotation key；
- 页码和精确位置；
- 创建时颜色；
- 创建时内容签名 `marker_signature`；
- 固定所有者 `marker_owner = AcademicVocab`；
- 创建时间；
- 当前状态。

本地账本必须使用插件自己的持久化存储，并在 Zotero 重启后仍然存在。技术验证期间只允许存放在隔离开发 profile 中，不得读取或写入日常 profile。

云端 `zotero_markers` 记录不能单独证明删除权限。执行删除前，必须同时匹配本地账本、云端 marker、移除任务以及 Zotero 中实际存在的标注。

## 3. 创建标记

创建标记必须按以下顺序进行：

1. 用户确认保存单词和例句；
2. 生成稳定且可重试的捕获请求 ID，并先持久化创建意图；
3. 检查同一请求是否已经成功创建标记；
4. 检查目标文字是否与既有标注重叠，并仅用于记录和提示；
5. 创建一条独立的 AcademicVocab 紫色下划线标注；即使与人工标注重叠，也绝不修改人工标注；
6. 立即取得 Zotero 返回的精确 annotation key；
7. 写入本地所有权账本，再同步最小必要的云端 marker 元数据。

用户一次确认多条例句时，每条已选例句中的目标单词位置都必须作为独立标记处理，分别取得 annotation key、写入账本并关联对应 `example_id`。不得为未勾选的候选创建标记，也不得把多个位置伪装成一条无法单独验证所有权的记录。

批量处理中某一个位置与人工标注重叠时，仍可创建独立的 AcademicVocab 下划线；不得覆盖、改色、合并、拆分或删除人工标注。创建失败时只能报告该位置，也不得因此删除已经安全创建的其他标记。每个位置都必须能够独立重试和独立移除。

同一捕获请求重复点击、超时重试或程序重启，不得创建第二条标记。

如果目标选区与任何既有人工标注重叠，仍可保存单词、例句和来源，并可新增独立的 AcademicVocab 下划线；但不得创建、覆盖、改色、合并、拆分或删除既有人工标注。

如果 Zotero 标注已经创建但本地账本写入失败：

- 只有仍能确定“本次刚创建的精确 annotation key”时，才可在同一操作中移除该条标注；
- 无法确定精确身份时，必须停止并记录错误；
- 不得依据颜色、文字、页码、位置相似度或标签猜测并删除标注。

## 4. 所有权不能推断

以下信息单独或组合出现，都不能证明标记属于 AcademicVocab：

- 颜色相同；
- 高亮文字相同；
- 页码或位置相同；
- 标签、批注文字或备注相同；
- 云端存在一条相似记录；
- 标注看起来像插件曾创建；
- 另一次安装或另一个 profile 保存过相似账本。

只有精确 attachment key、annotation key、`marker_owner`、创建签名和本地账本共同匹配，才可以进入移除检查。

## 5. 用户修改后的保护

自动清理前必须重新读取实际 Zotero 标注并计算签名。如果仅颜色变化、其余字段和精确所有权仍一致，普通“核验所有权”可恢复插件规定的亮紫色。若用户修改了文字、位置、批注、标签或其他会改变非颜色签名的内容：

- 将 marker 状态设为 `protected_modified`；
- 不自动恢复旧内容；
- 不自动改动文字、位置、批注或标签；
- 不自动删除；
- 向用户说明该标记因人工修改受到保护。

本地账本丢失、损坏、卸载后未恢复，或重新安装后身份无法验证时，也必须拒绝删除。不得通过扫描相似标注重建删除权限。

## 6. “不再复习”后的移除流程

用户确认“不再复习”后，单词、例句、来源和复习历史全部保留。标记移除按以下步骤执行：

1. 将 word 设为 `mastered`；
2. 为每条 active marker 创建唯一的 `remove_zotero_marker` 任务；
3. 插件取得任务后，核对用户、library、parent item、attachment 和 annotation key；
4. 核对本地账本中的 `marker_owner = AcademicVocab`；
5. 核对创建签名与 Zotero 中实际标注；
6. 全部一致时，只按精确 annotation key 删除该一条标注；
7. 记录结果并把 marker 和任务设为已完成。

如果目标标注已经不存在，记录“目标已不存在”的审计结果，并幂等完成任务，不寻找或删除替代标注。

如果身份不一致，返回 `MARKER_OWNERSHIP_UNVERIFIED`，不得删除。若仅签名不一致但本地账本仍精确证明 `marker_owner = AcademicVocab`、library、attachment 和 annotation key，用户可在“不再复习”操作中额外明确确认“同时移除这个 AcademicVocab 标记”；这属于用户直接授权，绝不作为后台自动清理。该确认不能删除任何人工标注，也不能依据相似文字、颜色或位置寻找替代标注。

## 7. 故障与恢复原则

- 网络中断时不删除标记，保留待处理任务；
- 同一移除任务重复执行，只能产生同一个结果；
- Zotero、附件或标注暂时不可用时，安全失败并等待人工处理或有限重试；
- 附件被移除后不得在其他附件中搜索相似标注；
- 云端确认失败但本地已精确删除时，保留本地完成凭据，只重试确认，不再次删除；
- 日志不得记录 PDF 全文、私人正文、密钥或访问令牌；
- 任何不确定情况都以保留标注为默认结果。

## 8. 绝对禁止

- 删除、覆盖、改色或合并用户人工创建的 Zotero 标注；
- 修改 Zotero 原始 PDF；
- 直接修改 Zotero SQLite 数据库；
- 仅凭颜色、文本、页码、位置或标签删除；
- 仅凭云端记录删除；
- 在账本丢失后猜测恢复所有权；
- 在隔离技术验证中访问日常 Zotero profile、正式数据库或私人 PDF。
